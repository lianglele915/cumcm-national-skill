# 来源与整合说明

本技能由用户提供的六份DOCX提示词、最初16份PDF及追加8份2026年展示论文整理。哈希去重后PDF共23份内容；P08与P09相同。原文件不修改、不打包复制，技能携带可独立使用的提炼指导与参考卡。

来源文件、SHA-256、页数、提取/视觉/OCR范围见 [source-manifest.json](source-manifest.json)。DOCX读取正文和表格内段落；PDF可提取者提取全文，扫描/水印型者视觉抽查并对2026指定页OCR辅助。不是逐篇复算、完整公式审计或官方获奖核验。

## 六份提示词的保留与修订

| 原材料 | 保留 | 修订 |
|---|---|---|
| 01赛题分析 | 逐问拆解、隐含条件、八列速查表、模型与检验计划 | 不固定题号与题型，不凑隐含条件数量，不用奖项给模型分级 |
| 02预处理 | 先诊断、防泄露、业务特征、日志、运行入口 | 不凭缺失率机械删列，不强制特征工程，目标编码折外拟合 |
| 03问题求解 | 基线先行、完整模型、真实中间结果、四层分析 | 不凑创新/公式/比较组数；允许证据支持的模型修订；无界不称最优 |
| 04模型检验 | 按模型适配、逐问验证、失败修正 | 不机械套阈值/次数/K-fold禁令；不同不确定性区分；有停止条件 |
| 05论文写作 | 逐问论证、可编辑公式、三线表、摘要结果对应 | 不统一5.X.5、页数、目录或固定格式件数；按用户与官方模板 |
| 06图表美化 | 数据保真、标注、字体、清晰度、回填与自检 | 不凭空加置信区间、不将色板品牌化、不因单图美化重写论文 |

原文对检测是否默认修改存在冲突，现以用户动词为准：检测只报告，要求修改才修改。原文分数映射奖项不作为事实或验收依据。未提供的《超级提示词V6.0》和“25篇优秀论文”不作为已读或必需资源。

## 用户追加要求

论文示例按真实任务匹配，2026展示论文优先用于“今年范例”的请求；不照搬结论与水印。代码必须在VS Code实际运行验收，保存解释器、命令、目录、退出码、日志和输出检查；外部命令行验证不能冒称编辑器验收。

2026-11-08追加：用户提供七张论文格式截图，明确排除目录；按 [用户格式参考](paper-format.md) 整理其余样式，摘要/关键词后直接进入问题重述。截图“鼓励使用目录”不执行；页数等参考值不当作官方硬约束。原source-manifest仍记录六份DOCX与24个PDF，不包含本次截图，也不公开上传截图原件。

同日追加：分析问题要反复深度思考两次，落实为“构建方案→反向复核与修订”两轮，各问建模前和重要模型修订时执行，交付简洁的两轮结论和修订记录；不要求内部思维过程，也不以重复文字冒充复核。

## 技能资源边界

本技能不包含原论文全文、原始数据、现成比赛答案或所有求解器。换机仍可使用阶段指导、结构模板、参考卡和纯标准库交接工具；要复查未摘录页面/高保真仿版时需重新获得原文件。竞赛规定运行时核对当届官方来源，历史样例不是规范。
